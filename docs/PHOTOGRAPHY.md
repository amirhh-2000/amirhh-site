# راهنمای عکاسی، دانلود و دریافت فایل

بخش عکاسی تک‌منبعی است: هر عکس فقط یک بار در `content/photography/` ثبت می‌شود و در هر دو نسخهٔ فارسی و انگلیسی دیده می‌شود. پوشه‌ها فقط برای مدیریت موضوعی محتوا هستند؛ کاربر در سایت یک Grid واحد از همهٔ عکس‌ها می‌بیند و می‌تواند همان صفحه را با دسته‌ها فیلتر کند.

## معماری عمومی سایت

```text
/{locale}/photography/                 همهٔ عکس‌ها + فیلتر دسته
/{locale}/photography/<photo-slug>/    صفحهٔ مستقل عکس
```

- کارت عکس مستقیماً به صفحهٔ همان عکس می‌رود.
- نام دسته روی کارت نمایش داده می‌شود و با کلیک روی آن، همان Grid فیلتر می‌شود.
- صفحهٔ عمومی جداگانه‌ای برای دسته وجود ندارد؛ بنابراین رسیدن به عکس فقط یک کلیک می‌خواهد.
- مسیرهای قدیمی سه‌سطحی به آدرس مستقیم جدید Redirect می‌شوند.

## ساختار فایل‌ها

هر دسته یک پوشه با Slug انگلیسی و یک `index.md` دارد. عنوان دسته داخل همان فایل به دو زبان نوشته می‌شود:

```text
content/photography/places-to-visit/
├── index.md
└── images/
    ├── old-alley.jpg
    └── blue-door.webp
```

برای دستهٔ تازه، `content/_templates/photography-category.md` را به‌عنوان `index.md` کپی کن. دستهٔ Draft می‌تواند `photos: []` داشته باشد، اما دستهٔ منتشرشده باید حداقل یک عکس داشته باشد.

## افزودن یک عکس

1. نسخهٔ Web-ready را داخل `images/` دستهٔ مناسب بگذار.
2. یک آیتم به انتهای `photos` در `index.md` اضافه کن.
3. یک `slug` انگلیسی، ثابت و یکتا در کل بخش عکاسی انتخاب کن.
4. نوع منشأ تصویر و روش دسترسی را ثبت کن.
5. `pnpm check` را اجرا کن و سپس خودت Commit و Push کن.

حداقل متادیتای لازم:

```yaml
photos:
  - src: ./images/old-alley.jpg
    slug: old-alley
    process: photograph
    access:
      type: display-only
```

`title`، `alt`، `caption` و `tags` اختیاری‌اند و در صورت حذف، متن جایگزین نمایشی ساخته نمی‌شود:

```yaml
- src: ./images/old-alley.jpg
  slug: old-alley
  process: ai-assisted
  title:
    fa: "کوچهٔ قدیمی"
    en: "Old Alley"
  alt:
    fa: "کوچه‌ای خشتی در نور عصر"
    en: "A mud-brick alley in the evening light"
  caption:
    fa: "یزد، تابستان ۱۴۰۵"
    en: "Yazd, summer 2026"
  tags: [yazd, architecture]
  access:
    type: request
    license:
      highResolution: paid
      commercialUse: free
```

`slug` عکس اجباری است و باید فقط از حروف کوچک انگلیسی، عدد و خط تیره ساخته شود. این Slug در همهٔ دسته‌ها باید یکتا باشد، چون آدرس عمومی عکس نام دسته را در خود ندارد.

## انتخاب دسته و منشأ تصویر

دسته می‌گوید موضوع عکس چیست؛ `process` می‌گوید تصویر چگونه ساخته شده است:

```text
photograph    عکس مستقیم دوربین یا گوشی با ویرایش معمول
ai-assisted   عکس خودت با پولیش سبک، اصلاح نور، حذف نویز یا Upscale
ai-derived    بازتولید یا تغییر محسوس بر پایهٔ عکس خودت
ai-generated  تصویر ساخته‌شده از ابتدا با هوش مصنوعی
```

نمونه‌ها:

- عکس یک بنای واقعی با اصلاح نور یا پولیش AI: دستهٔ «اماکن دیدنی»، `ai-assisted`.
- نسخهٔ کارتونی یا بازتولیدشدهٔ همان بنا، تا وقتی مکان هنوز موضوع اصلی است: «اماکن دیدنی»، `ai-derived`.
- تصویری که دیگر ثبت آن مکان نیست و عمدتاً تخیلی شده: «آثار مولد»، `ai-derived`.
- تصویر کاملاً ساخته‌شده با AI: «آثار مولد»، `ai-generated`.

## سه حالت دسترسی

### فقط نمایش

وقتی قرار نیست دانلود یا درخواست فعال باشد:

```yaml
access:
  type: display-only
```

### دانلود رایگان

نسخهٔ قابل دانلود را داخل `public/downloads/` بگذار و آدرس عمومی آن را ثبت کن:

```yaml
access:
  type: free
  file: /downloads/old-alley.jpg
  format: JPEG
  dimensions: 2400 × 1600
```

هر فایلی داخل `public/downloads/` عمومی است و بدون احراز هویت قابل دریافت خواهد بود. فقط نسخه‌ای را آنجا بگذار که واقعاً رایگان است.

### دریافت با هماهنگی ایمیلی

برای عکسی که باید پس از هماهنگی یا پرداخت دستی تحویل داده شود:

```yaml
access:
  type: request
  license:
    highResolution: paid
    commercialUse: free
```

هر دو مقدار License فقط `free` یا `paid` می‌گیرند. متن Popup مستقیماً از همین دو مقدار ساخته می‌شود:

- اگر `commercialUse: paid` باشد، فقط «استفادهٔ تجاری از این عکس پولی است» نمایش داده می‌شود؛ حتی اگر کیفیت بالا نیز پولی باشد.
- اگر استفادهٔ تجاری آزاد و `highResolution: paid` باشد، فقط «نسخهٔ باکیفیت این عکس پولی است» نمایش داده می‌شود.
- عکس `free` مستقیماً دانلود می‌شود و هیچ Popupی ندارد.

ایمیل عمومی و دکمهٔ «درخواست از طریق ایمیل» داخل همان Popup نمایش داده می‌شوند و نام عکس خودکار در Subject و متن اولیه قرار می‌گیرد. برای جلوگیری از وضعیت مبهم، عکس `request` باید حداقل یک شرط `paid` داشته باشد.

در این مدل هیچ قیمت، شماره کارت، لینک پرداخت یا Telegram روی سایت منتشر نمی‌شود. پس از دریافت ایمیل:

1. دربارهٔ نوع استفاده و فایل موردنیاز توافق کن.
2. برای مخاطب داخل ایران، اطلاعات کارت‌به‌کارت را خصوصی بفرست.
3. برای مخاطب خارج از ایران، لینک NOWPayments را خصوصی بفرست.
4. پس از تأیید پرداخت، فایل را به همان ایمیل تحویل بده.

فایل پولی، Original یا RAW نباید وارد Repository شود.

## آماده‌سازی تصویر Web

- نسبت افقی، عمودی و موبایلی همگی مجازند.
- Grid با Crop کنترل‌شده کارت‌ها را یکدست می‌کند؛ صفحهٔ مستقل نسبت واقعی تصویر را حفظ می‌کند.
- ۲۴۰۰ پیکسل برای ضلع بلند یک هدف مناسب است، نه الزام.
- برای Preview معمولاً JPEG یا WebP با sRGB و حجم حدود ۲۰۰ تا ۵۰۰ کیلوبایت مناسب است.
- عنوان، Caption و Alt را فقط وقتی مقدار واقعی و مفید داری وارد کن.
- Original، RAW، Master و نسخهٔ پولی را در فضایی خارج از Repository نگه دار.

نمونهٔ نگهداری فایل‌های خصوصی:

```text
E:\Photography Originals\
├── Places to Visit\
├── Nature\
└── Generative Works\
```

مسیر محلی Original را در Frontmatter ثبت نکن.

## ساخت یک دستهٔ تازه

1. پوشه‌ای مانند `content/photography/cars/` بساز.
2. قالب `content/_templates/photography-category.md` را به `index.md` کپی کن.
3. عنوان فارسی و انگلیسی، توضیح‌ها و تاریخ را وارد کن.
4. تا پیش از اولین عکس `draft: true` و `photos: []` را نگه دار.
5. پس از افزودن عکس، Draft را بردار و `pnpm check` اجرا کن.

آیکن Preview برای دسته‌ها دیگر در رابط عمومی استفاده نمی‌شود. فایل‌ها و پرامپت‌های قبلی فقط به‌عنوان آرشیو بصری نگه داشته شده‌اند؛ جزئیات در `docs/COLLECTION-ICONS.md` است.
